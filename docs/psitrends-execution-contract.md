## Required detail within phases

**Access matrix:** use `FULL / WRITE / READ ONLY / NO ACCESS / NOT VERIFIED` separately for Joomla login and ACL; article create/edit/publish/unpublish; menus; modules; Quix/Helix templates/pages; media; extension install/update/remove; users; global configuration; cache; database tools; file manager; SFTP/SSH; Hetzner; DNS; SSL; scheduled jobs; backup/restore; GA4/GTM; Search Console; GBP; Cloudflare Pages/Web Analytics. One edit proves only that permission.

**Secret handling:** prefer Keychain/existing credential manager, then approved secrets manager, then existing/private encrypted storage outside every repository with mode 0600 where appropriate. Preserve an existing secure location if programmatic persistence is unavailable. Git contains only aliases, service/login URL, storage/retrieval/recovery pointers, resource-owning account alias and last verification date. Never store usernames, passwords, cookies/session IDs, tokens, recovery codes, private backup bytes or raw client data in Git/issues/reports.

**System inventory:** exact Joomla/PHP/database versions; active templates/styles; Quix/Helix versions/configuration; extensions/plugins/modules/components; menu trees/positions; languages; privacy-safe role inventory; media; forms/contact routes; analytics IDs; robots/sitemaps/canonicals/redirects; cron; custom CSS/JS/overrides; hosting/DNS topology; integrations; public URLs. Prior reported Joomla 4.4.0, PHP 8.1.34, nginx/Hetzner and `/var/www/html` are historical, not verification. `sales` is not Joomla production source; supported CMS/template controls are the known historical edit path; core write access is unproven.

**URL inventory fields:** URL, locale, HTTP status, title, H1, canonical, robots/indexability, page type, offer/status, topic, CTA, language quality, claim/title risks, inlinks/outlinks, available Search Console/GA4/backlink evidence and proposed action. Use `KEEP / UPDATE / MERGE / 301 / ARCHIVE_INDEXED / NOINDEX / DELETE_AFTER_VERIFICATION`. Inspect traffic, authority and links before removal; never mass-delete or mass-redirect because content is old.

**Audit coverage:** support/security/update status and provenance; ACL/MFA/admin exposure; permissions/private stored data; TLS/headers/mixed content; errors/debug; spam/forms; backups/off-site recovery; scheduled jobs; unused components; broken links/404s/redirect chains/duplicates; canonical/multilingual behavior; TTFB/cache/compression; template-level LCP/INP/CLS, mobile payload, images/dimensions/lazy loading, fonts, embeds, scripts and duplicate libraries; mobile rendering/accessibility; privacy/consent. SEO includes indexed/excluded pages, robots/sitemaps, title/H1/meta, hreflang, schema, alt text, internal links/crawl depth/orphans, thin/legacy content, queries/pages, brand/non-brand/local performance, authority and GBP consistency. Audit positioning, active services, English/Russian journeys, trust, practical details and all existing acquisition funnels. Do not sacrifice functionality for synthetic scores.

**Claims table:** `URL | exact phrase | context/type | evidence/status | risk | proposed replacement/action`, with `KEEP / REWRITE / REMOVE / LEGAL-VERIFY`. Search EN/RU equivalents of psychotherapist/psychotherapy, professional psychologist, therapy/treatment, trauma, healing/health/symptoms/depression/cure/recovery, removing fears/blocks, homeopath/qualification, rapid/guaranteed transformation, financial/business outcomes and factual prediction/clairvoyance claims. Verify current entitlement from authoritative sources; distinguish historical training, certifications and regulated registration. Preserve legitimate education without implying Canadian equivalency. Homeopathy is not a primary acquisition pillar until status/scope is verified.

**IA/copy:** PsiTrends umbrella; Holistic House/Andrey practice identity; Academy learning archive; Toronto Tantra separate community/events funnel, subject to evidence-based naming resolution. Roughly 5–7 primary navigation items. English serves Toronto acquisition; Russian retains a deliberate current-services/library journey, without forced translation parity. Use true-equivalent hreflang, appropriate `en-CA`/`ru`, documented `x-default`, equivalent language switching and unmixed metadata. Preserve systemic mapping → parts/pattern work → experiential hypnosis/guided work where appropriate → integration/optional symbol; do not imply everyone receives every modality.

Homepage specification includes hero, client situations, four-step process, up to three core services, safety/expectations, curated proof, About, Academy gateway and final CTA. Service specifications include intent, explanation/process, fit/scope, FAQ, practical facts and CTA. About verifies background/training/title/location; Contact verifies channels, fees/duration and minimal-data enquiry; Academy distinguishes current/educational/historical. Explain constellations as experiential reflection, not proof about absent people/history. Business page needs service/demand evidence and no financial/legal advice or guaranteed growth. Symbolic integration is optional; Reiki is supporting if justified. Review a simple first-session/optional three-session offer without inventing availability. Professional English copy is mandatory; use grounded human visuals, authentic consented images, readable mobile layouts and one primary next action. Avoid fake urgency, generic spiritual stock, testimonial screenshot walls and doorway pages.

**Analytics/trust:** retain consented GA4/Cloudflare and existing `contact_click`, dimensions `landing_page`, `contact_method`, `acquisition_source`, and GBP UTM convention; verify no duplicate pageviews/events. Weekly scorecard: GBP visibility/clicks/calls/directions where available, organic impressions/clicks, acquisition sessions, contact method/source, real enquiry, qualified enquiry, booked session, paid client, actual revenue and reviews. Missing business records are unavailable, not zero; clicks never imply bookings/revenue. North star: qualified paid clients / relevant acquisition visits. No heavy CRM/scheduler or underpowered A/B testing without workflow/volume justification. Maintain consistent GBP identity/location/hours/services and leave primary category unchanged during this task unless explicitly authorized later. Prepare neutral requests using the verified GBP review URL; never message clients without explicit authorization. Curate 3–6 consented proof examples; separate Google reviews, testimonials and contextual cases, avoiding causal/typical extraordinary-outcome implications. Audit privacy, consent, service terms and cancellation/refund provisions where relevant; no sensitive health details in first contact, analytics or URLs.

**Academy statuses:** `CURRENT OFFER / EDUCATIONAL RESOURCE / HISTORICAL PROGRAM / CLAIM REVIEW / MERGE`; taxonomy covers archetypes, constellations, mysteries/traditions, Reiki, mandalas/artifacts, books, videos/meditations and historical programs. Later content clusters must follow actual demand after service/technical stability.

**Platform decision:** score modernized Joomla, hybrid first-party acquisition plus Joomla Academy, and full migration on support/security, editing, Codex/team maintainability, SEO, languages, performance, integrations, recovery, cost, effort and ownership. Recommend one with evidence after compatibility tests; newer technology is not sufficient justification. Any migration needs URL/301 map, metadata/canonical preservation, content parity decisions, analytics comparison, Search Console monitoring and rollback window.

## Source tensions and operational interpretation

1. The original body is audit/roadmap-oriented; the latest execution prompt and current instruction require implementation in gated stages. Meeting the older audit-only criteria is insufficient for the current request.
2. The master plan permits modernization before acquisition if security requires it; the current user instruction specifies strict sequence. Preserve that order and do not bypass safety gates; report any incompatible security prerequisite rather than silently reordering a risky release.
3. The master plan says to approve architecture; the current instruction rejects routine approval stops. Make the architecture concrete and reviewable within authorization; ask only for an unresolved irreversible business choice, legal fact or owner authentication.
4. Sources qualify fresh-session testing/staging with “where practical/possible”; the current instruction demands verified recoverability/backup/rollback/staging before dependent work. An unavailable staging path remains a real dependency, not a passed gate.
5. Proposed brand labels, slugs, package structure and Business page are hypotheses, not permission to invent facts. Legal claims and dated platform support assertions require current authoritative verification.
